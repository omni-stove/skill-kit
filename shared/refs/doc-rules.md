# Rules for setting and design documents

Write only what the user's input and the project's files give. The format's sections are a menu: leave out any section with nothing to put in it, and any detail the user says to leave to you.

Leave out what the name, the category, or the project readme already shows.

State what is, what happens, or what the value is. Leave out commentary on role, importance, theme, or the effect on the reader or player.

Write `TBD` only for a value the document needs and the user has not fixed, with what decides it.

Ask only what the document structurally needs and the input does not give, in one `AskUserQuestion` round.

If the file exists, read it and edit in place.

Present the draft, check it against the project readme or GDD and the existing documents, confirm with the user, then write.
